# 人类 Agent 使用指南 08：别再逼自己自律了，给人生写一份 AGENTS.md

写到第八篇，我发现一个挺讽刺的问题：我们已经学会给 AI 编写系统指令，却从没认真定义过自己应该如何运行。

给 AI Agent 配置 System Prompt、Memory、Tools、Execution Rules。轮到自己，只剩“明天一定努力”“以后不能再拖延”。

System：Undefined。
Executor：Unstable。
Error：Repeated。

## 01｜为什么写 HUMAN_AGENTS.md？

AGENTS.md 在 AI 编程场景中，可以告诉 Agent 如何理解项目、遵守规则和执行任务。

人类当然不是程序，但我们可以借鉴系统设计：精力有限就设置预算；信息太多就管理上下文；思考过度就设置停止条件；判断可能出错就寻找证据；失败反复发生就更新记忆；计划无法落地就拆分任务；重复工作太多就调用工具。

**系统的意义不是控制自己，而是减少不必要的内耗。**

## 02｜个人 Agent 的七个核心模块

**Token Budget：** 每天优先完成一个核心任务。

**Context：** 新想法先记录，不随意打断当前工作。

**Thinking：** 低风险快速试错，高风险深入验证。

**Hallucination：** 区分事实与假设。

**Memory：** 把反馈转化为下一次行动改进。

**Executor：** 把目标拆成具体动作，用产出衡量进展。

**Tools：** 自动化重复工作，重要判断留给自己。

Goal → Plan → Execute → Feedback → Memory → Update。

## 03｜HUMAN_AGENTS.md 模板

完整可复制的个人操作手册放在仓库根目录：[HUMAN_AGENTS.md](../HUMAN_AGENTS.md)。

包含 MISSION、TOKEN_BUDGET、CONTEXT、THINKING、ANTI_HALLUCINATION、MEMORY、EXECUTOR、TOOLS、RECOVERY、REVIEW 十个模块。

## 04｜别把系统设计变成拖延

花三个小时设计个人操作系统，再花两个小时研究效率工具，最后把 Notion 装修得像一家科技公司。第二天继续刷 X。

Planning：Perfect。
Execution：Zero。

**系统存在的意义，是让行动更容易发生，而不是让规划更复杂。**

每次升级，只修改真正影响执行的一两条规则。

## 05｜持续 Debug

软件会有 Bug，Agent 会执行失败，人类当然也会。

发现问题 → 记录反馈 → 修改规则 → 重新运行。

**好的系统不是永远不出错，而是出错后能够恢复。**

## 06｜写在第一季最后

从 Token 到 Context，从 Thinking 到 Hallucination，从 Memory 到 Executor，再到 Tools 和 AGENTS.md。

AI Agent 值得学习的，不只是它能完成多少任务，还有背后的系统设计思路。

什么时候思考，什么时候行动，什么时候调用工具，什么时候应该休息。

**人不是为了成为一台完美的机器。**

学习系统化思维，是为了把有限的注意力留给真正重要的事情。

不用完美，先写第一版，然后让现实帮你 Debug。
