# 人类 Agent 使用指南 05：你不是没有成长，而是 Memory 根本没写入成功

> 版本说明：根据对话中可见的已确认稿整理的 GitHub 阅读版，未与 X 原帖逐字核对。

最近研究 AI Agent 的 Memory 机制时，我发现一个扎心的问题：我们知道 AI 需要长期记忆，却总以为人类经历过一次，就会自动吸取教训。

项目失败：“下次一定先验证需求。”运营账号没效果：“以后一定认真分析数据。”过了一个月，同样的错误再次出现。

Memory：Not Found。
Error：Repeated。

## 01｜经历不等于经验

一篇帖子爆了很开心，下一篇数据差很失落。但如果没有记录爆款主题、开头、评论区和用户反馈，下次依然全凭感觉。

**经历是发生过的事情，经验是能指导下一次行动的信息。**

## 02｜只保存情绪，不保存规则

AI 工具开发两周没人使用。记住“创业太难了”，不如记录“开发前没有找到愿意持续使用的目标用户”。

好的 Memory，不是记录自己有多惨，而是记录下次应该怎么做。

## 03｜三层 Memory

**Working Memory：** 当前项目、待办和下一步行动。

**Episodic Memory：** 关键事件与实际结果。

**Semantic Memory：** 从经历中提炼的可复用规则。

它们分别回答：现在做什么？过去发生了什么？以后应该怎么做？

## 04｜别把复盘变成自我感动

复盘几千字，最后一句“以后一定更加努力”，就像给 AI 输入“请你下次表现得更好”。

我现在只问三个问题：预期是什么？实际发生了什么？下一次改变哪个动作？

## 05｜Memory.md

```md
Working: 当前目标与下一步。
Episodic: 关键事件与真实结果。
Semantic: 可复用的经验规则。
Trigger: 相似问题时主动检索。
Update: 新证据出现时修正规则。
Review: 每周整理重要经验。
```

记忆不是越多越好。保存一切却从不检索，只是制造越来越大的数据库。**真正重要的不是 Storage，而是 Retrieval。**

## 06｜成长是减少重复错误

有人做十个项目，只是同一个错误犯了十遍；有人做三个项目，不断修正方法，反而进步更快。

**真正的成长，不是人生运行了多少次，而是系统有没有完成版本更新。**
